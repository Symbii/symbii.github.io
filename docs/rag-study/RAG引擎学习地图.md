# RAG 引擎学习地图

> 适用对象：有 Python 基础、用过 LLM 的人，目标是把 RAG 从 0 做到生产可用。
> 使用方式：按阶段推进，每个阶段都有动手产出和验收标准，不达标不进下一阶段。
> 总周期：8 周 × 每周 8–10 小时，可以拉长，但别跳阶段。

---

## 0. 终点能力（学完能做到什么）

目标用产出定义，不用"了解"这种词。学完应该能：

1. 拿到一批真实文档（PDF、Word、网页混在一起），独立跑完解析、切分、索引、检索、生成的全链路，答案带引用。
2. 面对答错的 case，30 分钟内定位到解析、切分、召回、排序、生成、权限里的哪一环，而不是盲调参数。
3. 建一套 100+ 题的评测集，每次改动给出指标变化和归因，而不是"感觉好多了"。
4. 设计文档级和行级的权限过滤方案，并且写得出越权测试用例。
5. 说清楚什么情况下不该用 RAG：长上下文能解决的、结构化查询能解决的、数据本身在实时变化的。

---

## 1. 三条贯穿主线

三条线要并行推进，少一条就只剩调框架：

| 主线 | 内容 | 为什么重要 |
|---|---|---|
| 概念线 | 每个环节"为什么会失效"的机理 | 决定你能不能定位问题 |
| 代码线 | 手写 → 框架 → 生产化，三段式 | 先懂再快，避免被框架绑架 |
| 评测线 | 从第 2 周就建立评测集 | 没有度量就没有优化 |

先手写一遍最朴素的 RAG，100 行以内，再上框架。检索漏斗自己搭过一次，看框架源码时才不会迷路。

---

## 2. 阶段地图

### S0 基础底座（2–3 天）

这一段要建立的是检索这件事的物理直觉。概念上过一遍 token 与上下文窗口、embedding 与余弦相似度、向量索引原理（HNSW / IVF / PQ）、BM25 的词频-逆文档频率、注意力机制与 Lost in the Middle。

动手四件事：用 numpy 手写 cosine top-k 检索；用 bge 或 sentence-transformers 生成 embedding；用 `rank_bm25` 跑一遍关键词检索；对比同一个 query 下向量召回和 BM25 召回的差异。

验收标准是能解释为什么向量检索会漏掉精确的关键词匹配，比如型号、人名、错误码。

### S1 数据接入与解析（1 周）★差异化最大

这一段解决的是把真实世界的脏文档变成可检索的干净文本。概念包括版式还原、阅读顺序、双栏、表格结构、扫描件 OCR、页眉页脚和水印噪声。

工具按用途挑：PyMuPDF / pdfplumber 做版式，PaddleOCR 处理扫描件，Camelot 或 PP-Structure 抽表格，python-docx / python-pptx / openpyxl 读 Office，trafilatura 抓网页正文。

动手要收 50 份真实文档，别拿干净的示例 PDF 充数；写解析 pipeline，按文档类型统计失败率；再建一个脏数据样本集，专门放解析出错的 case。

验收：双栏论文、跨页表格、扫描件三类文档都能还原出正确阅读顺序，并且说得出每类的典型失败模式。

### S2 切分与索引（1 周）

切分方式直接决定召回上限，后面检索做得再好也补不回来。概念要过固定窗口、递归切分、语义切分、按标题层级切分、父子块（small-to-big）、句子窗口，还有元数据设计：标题路径、页码、来源、时间、权限标签。

向量库在 Milvus / Qdrant / pgvector / FAISS 之间选型，HNSW 的 M、efConstruction、efSearch 各自如何影响召回率与延迟要弄明白。混合索引是把向量、BM25、标量过滤组合起来。

动手：同一批文档做 3 种切分策略，用固定的 20 道题测 Recall@5，把实验表格记下来。验收时要拿得出一份切分参数到召回率的实验记录，而不是拍脑袋定 chunk size。

### S3 检索与重排（1.5 周）★核心竞争区

目标是让召回率和排序质量变得可解释、可优化。

召回侧走 dense / sparse / hybrid，RRF 融合，多向量（ColBERT 思路）。Query 理解包括改写、多查询扩展、HyDE、子问题拆解、意图路由。过滤要处理元数据、时间和权限，预过滤与后过滤对召回的影响不一样，这是权限正确性的关键。

重排用 cross-encoder（bge-reranker）或 LLM rerank，区别在成本与延迟的取舍。上下文组装要做去重、邻近块扩展、token 预算分配、引用编号。

动手在 100 题评测集上做四组 A/B：纯向量；混合召回；混合加 rerank；再加 query 改写。每组记 Recall@k、nDCG@10、P95 延迟、单次成本。

验收是能画出完整的召回漏斗，从候选到过滤到重排再到入 prompt，并指出瓶颈卡在召回还是排序。

### S4 生成与编排（1 周）

目标是答案可信、可追溯、该拒答时拒答。概念包括 grounded generation、引用标注、无答案判定、多轮指代消解、会话压缩、流式输出。编排上要碰工作流和 Agent、工具调用、多模型路由与降级。

动手三件：实现 answer-with-citations，引用能点回原文段落；构造 20 道知识库里没有答案的问题，测拒答率与误拒率；做一次 prompt 模板加模型组合的对比实验。

验收：引用能定位到原文，无答案问题的拒答率超过 80%，同时误拒率可接受。

### S5 评测与可观测（1 周，越早开始越好）★分水岭

这一环是把感觉变成数字。检索指标看 Recall@k、MRR、nDCG、命中率；生成指标看 faithfulness（忠实度）、answer relevancy、context precision/recall；业务指标看解决率、人工采纳率、平均轮次。

方法上要做评测集构建（真实问题 + 标准答案 + 金标文档片段），注意 LLM-as-judge 的位置偏差和长度偏差，还要有回归测试。工具可选 RAGAS、TruLens、Langfuse / LangSmith、OpenTelemetry trace。

动手：建 100 到 200 题评测集，接进 CI，每次改动自动跑回归并输出对比报告。验收要求任意一次改动都能给出哪个指标变了、变了多少、归因到哪一环。

### S6 工程化：权限、多租户与部署（1 周）★企业硬指标

这一段是从 demo 走到可交付。权限部分要有文档级和行级的 ACL 模型，权限同步走 LDAP / SCIM 或组织架构，过滤必须下推到检索层，不能检索完再删，另外还要有审计日志。多租户要定隔离级别，独立库、独立表还是行级 tenant_id，各自代价不同，配额与限流也得有。部署涉及私有化、信创适配、容器化、水平扩展、缓存策略。成本要算 embedding 与 rerank 的调用量、Token 成本。

动手：给现有系统加上部门隔离，写 10 条越权测试用例，覆盖跨部门、跨租户、已删除文档。验收要求越权测试全绿，并能估算 100 万文档规模下的月度成本与 P95 延迟。

### S7 进阶方向（选 1–2 个，各 3–5 天）

Agentic RAG 是计划、检索、反思、再检索的循环，Self-RAG 和 CRAG 提供批判与纠错机制，检索本身被暴露成工具原语。GraphRAG 做实体关系抽取、社区摘要，擅长多跳与聚合型问题，代价在成本与更新。多模态检索处理图表、图片、版面理解，以及跨模态 embedding。长上下文与 RAG 的取舍在于，什么场景下直接把文档塞进上下文更划算，边界在哪。

动手任选一个做可运行 demo，用 S5 的评测集与基线对比，给出是否值得上的结论。

## 3. 八周节奏表

| 周 | 主题 | 周末交付物 |
|---|---|---|
| W1 | S0 + 跑通朴素 RAG | 100 行以内的 naive RAG，能对 50 份文档问答 |
| W2 | S1 解析攻坚 + 建首批评测题 | 解析 pipeline + 30 题评测集（含金标片段） |
| W3 | S2 切分实验 | 3 种切分策略的 Recall@5 对比报告 |
| W4 | S3 混合召回 | 向量 vs BM25 vs 混合（RRF）的对比报告 |
| W5 | S3 重排 + 上下文组装 | 加 rerank 的 A/B 报告（质量 / 延迟 / 成本三角） |
| W6 | S4 生成 + S5 评测闭环 | 带引用与拒答的问答 + 100 题评测集接入 CI |
| W7 | S6 权限与部署 | 部门隔离方案 + 越权测试用例 + 成本估算 |
| W8 | S7 进阶 + 复盘 | 一个进阶 demo + 全链路复盘文档 |

> 只有 4 周的话：W1 与 W2 合并，W3 到 W5 合并成检索攻坚，W6 的评测必做，S6 和 S7 选做。

## 4. 项目阶梯（能力证明）

按顺序做，每个都是可展示的产出：

- P0 最小可用：50 份文档，单文件脚本，带引用的问答。
- P1 检索优化：混合召回 + rerank，有量化对比报告。
- P2 评测闭环：100+ 题评测集 + CI 回归 + 归因分析。
- P3 权限隔离：多部门/多租户 + 越权测试。
- P4 生产化：增量同步、删除感知、监控告警、成本核算。
- P5 进阶：Agentic RAG 或 GraphRAG，并与基线做评测对比。

简历或汇报时，P2 和 P3 比 P0 有说服力得多，它们证明的是可运营，而不是能跑。

## 5. 精选资源

论文按学习顺序：

1. Lewis et al., *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks* (2020)，原始定义。
2. Liu et al., *Lost in the Middle* (2023)，上下文位置偏差，解释为什么要重排与压缩。
3. Malkov & Yashunin, *HNSW*，向量索引的工程基础。
4. Khattab & Zaharia, *ColBERT*，多向量/迟交互检索。
5. Asai et al., *Self-RAG*；Yan et al., *CRAG*，反思与纠错式检索。
6. Edge et al., *GraphRAG* (Microsoft)，图谱路线的代表。
7. Es et al., *RAGAS*，评测框架的指标定义。
8. Anthropic, *Contextual Retrieval*，切分上下文增强的工程实践。

文档与源码：

- Milvus / Qdrant 官方文档，看索引参数与过滤语义。
- Elasticsearch / OpenSearch 的 hybrid search 与 RRF 实现。
- LlamaIndex、LangChain 的检索抽象，读设计，不必全用。
- 开源项目读码：RAGFlow（解析链路）、Dify（编排与工作流）、FastGPT（知识库产品化）。

读码方式建议带着三个问题进去：它的召回漏斗长什么样、权限在哪一层过滤、评测怎么接。比通读源码有效。

## 6. 阶段自测清单

每完成一个阶段，不看资料回答这些问题：

- [ ] 向量检索和 BM25 各自会在什么 query 上失效？混合时如何融合分数？
- [ ] 双栏 PDF 解析错乱会导致什么下游问题？如何在评测中暴露它？
- [ ] chunk 变小为什么召回率会升、但生成质量可能降？父子块怎么解决？
- [ ] 预过滤和后过滤在权限场景下分别有什么风险？
- [ ] rerank 提升了 nDCG，但端到端答案没变好，可能是什么原因？
- [ ] 如何判断一次答错是"没召回"还是"召回了但没用好"？
- [ ] LLM-as-judge 有哪些系统性偏差？如何校准？
- [ ] 文档被删除后，索引、缓存、引用分别要怎么处理？
- [ ] 什么情况下应该放弃 RAG，改用长上下文或结构化查询？
- [ ] 100 万文档、100 QPS 的场景，瓶颈最可能出现在哪一层？

## 7. 常见坑

1. 先学框架再学原理。会调 LangChain 但答不出为什么召回不到，等于没学。
2. 没有评测集就开始优化。所有效果变好了都无法证伪，最后变成玄学调参。
3. 只盯 chunk size。解析质量和 query 改写的收益通常远大于切分参数微调。
4. 权限后加。检索后再过滤会导致先越权拿到再删，既漏数据又泄露给日志；权限必须是检索的前置条件。
5. 迷信 GraphRAG 和长上下文。两者都有明确的成本与适用边界，先证明基线不够用再上。
6. 用干净样例数据自嗨。真实文档的解析失败率才是项目风险所在。
7. 忽略删除与更新。知识库不是只增不减，删除感知和增量重建是生产必答题。

## 8. 一页纸速记

```
解析 → 切分 → 索引 → 召回 → 过滤 → 重排 → 组装 → 生成 → 引用
  ↑                                              ↓
  └──────────── 评测（贯穿始终） ←───────────────┘
                权限（前置约束，不是后处理）
```

四项真正拉开差距的能力：解析质量、召回+重排、权限过滤、评测闭环。
