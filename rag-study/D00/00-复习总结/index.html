    D00 · 复习总结¶

    每天开工前的复习记在这里，按轮次往下加，不占学习日的编号。

    第二轮 · 2026-11-27 · D01 综合题（4 问）¶

    场景题：运维问答助手，问「备份任务失败，日志报 disk full 怎么排查」，系统答成「备份成功后请检查备份策略」；检索回的是「成功日志」节 + 「磁盘空间规划建议」节，没回「disk full → 清理哪些目录」。1200 chunk、上周导入、20 条抽检全过。

    小问 考点 结论
    (a) 用 8 环编号定位故障 半对，方向对、未编号；字面大于语义混淆 BM25 与稠密向量
    (b) 设计能归因的最小实验 半对，第一版答成修复方案；第二版方向对，缺没召回分支
    (c) 重排能否替代修上游 对，候选池结论对；cross-encoder 机制说成逐 token 重排
    (d) 检索正确但答案错，属哪一环 错，答编码阶段，实为生成环节

    (a) 定位环节¶

    答案（原文要点）：首选检索阶段 KNN，理由是「字面大于语义导致向量匹配度高，正确段落没进 top-k，重排也救不回来」；第二可能 chunk 阶段，「切分把 disk 和 full 拆开，上下文丢了」。

    池子里没有就重排救不了，这一条完全正确，也正是 (c) 的答案基础。切分把 disk / full 劈开这个故障形态也猜得准。

    错在两处。一是字面大于语义把两种检索混了，稠密向量不做字面匹配，字面匹配是 BM25；字面压过语义只在混合检索 BM25 权重过高时成立，对应 rag/nlp/search.py:39 build_fusion_expr(topn, vector_similarity_weight=0.3) 那个权重，属 ⑥ 检索的融合参数，不是 KNN 性质。二是没用上 20 条抽检全过这条证据，它证明 ④⑤ 整体没坏，但抽检不含 disk full 这类长尾查询，不能排除 ③。

    补充一点，诊断顺序按验证成本排，不按可能性排。③ 翻 chunk 原文 1 分钟，④ 换编码模板 10 分钟，⑥ 调 top-k/融合权重、建评测集要半天。

    (b) 最小实验¶

    第一版：把手册那章改成「备份任务失败，日志报 disk full，排查手段」。

    这是修复方案，不是诊断实验。三个问题：改文本同时改了措辞与切分边界，没法归因；要重解析、重编码 1200 chunk，最贵；还绕过了段落在不在库里这个二分。

    第二版：扩大 top-k，看正确答案是否被召回；召回则说明「向量空间差别大」，下一步比 query 与原文的编码差异。

    判定是通过，动作对、方向对（指向 ⑦）。缺三样：没写扩到 50 仍没有这个分支，实验得正反都能判读；没给具体数字，k 从几到几、期望排第几；向量空间差别大这个说法含糊。

    标准形态是两个互补动作。一是 top_k 10→50 看目标段排第几，出现就是 ⑧ 召回深度不足，仍不出现还不足以定罪 ③。二是按 doc_id 捞出该文档全部 chunk，看 content_with_weight 原文里 disk full 与排查手段是否同段，被劈开就是 ③ 有罪。

    (c) 重排能否替代修上游¶

    答案：①答案在 top-k 内可能救回，不在则无法挽救；②重排不改上游、候选池没变，只是「逐 token 重排」；③正确语句排前面就会让答案看起来变好。

    第 1 点满分。第 2 点里候选池没变是对的，但 cross-encoder 不是逐 token 重排，它是把 [CLS] q [SEP] d [SEP] 拼成一条做一次前向，从 [CLS] 取标量分数，逐候选对打分。这里还漏了成本和架构：cross-encoder 不能预计算、不能建索引，每条查询要对 K 个候选各跑一次前向。

    第 3 点方向对，但没点出指标类型。重排只改排序类指标，Precision@1、MRR、nDCG、Recall@10 会好看；召回类指标（Recall@池大小）一个不动。

    (d) 检索正确但答案写错数字¶

    答案：编码阶段出问题。这一问答错了。

    编码（④⑦）的产物是向量，只决定哪几段排前面。段落已经把正确内容带进来了，编码的任务就完成了，它没有能力把段落里的 80% 改成 50%。

    正确归属是 ⑧ 生成，LLM 的忠实性 / faithfulness 问题。常见形态是上下文里同时有 50% 与 80%（来自另一份文档），模型挑了错的那个，仍是生成侧的选择错误。

    两类故障的分界不是答得对不对，而是信息有没有进来。召回失败那一类，信息没进来，看 Recall@k / hit rate / MRR / nDCG@k；忠实性失败那一类，信息进来了被改写，看 faithfulness / groundedness / 引用准确率 / 数值一致性。

    诊断三步：固定上下文为正确段落，只换 prompt 或模型；删掉 80% 那段，若模型仍答 50% 就是纯幻觉；查上下文是否同时存在冲突数字，那是冲突消解问题。

    第二轮结论¶

    四问的判定是 (a) 部分对、(b) 补答一次后通过、(c) 大部分对、(d) 答错。

    一个反复出现的思维惯性：一看到答案不对，先怀疑向量或编码，(a) 首选检索、(d) 答编码都是这个路子。今天把它压成一句，编码只能决定看到什么，不能决定怎么用，数字写错是生成的事。

    还有一个格式习惯。实验要写成改 ＿ → 看 ＿ → 期望 ＿，而且正反两个结果都要能判读，否则做完了不知道该往哪走。
