# RAG 引擎学习地图

> 适用对象：有基础编程能力（Python 熟练）、了解 LLM 基本用法，想系统掌握 RAG 引擎从 0 到生产的人。
> 使用方式：按阶段推进，每阶段都有「动手产出 + 验收标准」，不达标不进入下一阶段。
> 总周期：8 周 × 每周 8–10 小时（可按需拉长，但不要跳阶段）。

---

## 0. 终点能力（学完能做到什么）

用可验证的产出定义目标，而不是"了解"：

1. 拿到一批真实文档（PDF/Word/网页混合），能独立完成解析、切分、索引、检索、生成的全链路，并给出带引用的答案。
2. 面对"答错了"，能在 30 分钟内定位是**解析、切分、召回、排序、生成、权限**哪一环的问题，而不是盲调参数。
3. 能建一套 100+ 题的评测集，把每次改动变成"指标变化 + 归因"，而不是"感觉好多了"。
4. 能设计文档级/行级权限过滤方案，并写出越权测试用例。
5. 能说清楚什么时候**不该用 RAG**（长上下文、结构化查询、实时数据）。

---

## 1. 三条贯穿主线

学习过程中始终并行推进这三条线，缺一条就会变成"只会调框架"：

| 主线 | 内容 | 为什么重要 |
|---|---|---|
| 概念线 | 每个环节"为什么会失效"的机理 | 决定你能不能定位问题 |
| 代码线 | 手写 → 框架 → 生产化，三段式 | 先懂再快，避免被框架绑架 |
| 评测线 | 从第 2 周就建立评测集 | 没有度量就没有优化 |

**关键原则：先手写一遍最朴素的 RAG（100 行以内），再上框架。** 手写过的检索漏斗，看框架源码时才不会迷路。

---

## 2. 阶段地图

### S0 基础底座（2–3 天）

**目标**：建立"检索"这件事的物理直觉。

- 概念：token 与上下文窗口、embedding 与余弦相似度、向量索引原理（HNSW / IVF / PQ）、BM25 的词频-逆文档频率、注意力机制与「Lost in the Middle」。
- 动手：
  - 用 numpy 手写 cosine top-k 检索；
  - 用 bge / sentence-transformers 生成 embedding；
  - 用 `rank_bm25` 跑一遍关键词检索；
  - 对比同一 query 下向量召回与 BM25 召回的差异。
- 验收：能解释"为什么向量检索会漏掉精确的关键词匹配（如型号、人名、错误码）"。

### S1 数据接入与解析（1 周）★差异化最大

**目标**：把真实世界的脏文档变成可检索的干净文本。

- 概念：版式还原、阅读顺序、双栏、表格结构、扫描件 OCR、页眉页脚/水印噪声。
- 工具：PyMuPDF / pdfplumber（版式）、PaddleOCR（扫描件）、Camelot 或 PP-Structure（表格）、python-docx / python-pptx / openpyxl、trafilatura（网页正文）。
- 动手：
  - 收集 50 份**真实**文档（不要用干净的示例 PDF）；
  - 写解析 pipeline，统计每类文档的解析失败率；
  - 建一个"脏数据样本集"，专门存放解析出错的 case。
- 验收：双栏论文、跨页表格、扫描件三类文档都能还原出正确阅读顺序；能说出每类文档的典型失败模式。

### S2 切分与索引（1 周）

**目标**：理解"切分方式直接决定召回上限"。

- 概念：固定窗口 / 递归切分 / 语义切分 / 按标题层级切分 / 父子块（small-to-big）/ 句子窗口；元数据设计（标题路径、页码、来源、时间、权限标签）。
- 向量库：Milvus / Qdrant / pgvector / FAISS 的选型差异；HNSW 的 M、efConstruction、efSearch 如何影响召回率与延迟。
- 混合索引：向量 + BM25 + 标量过滤的组合方式。
- 动手：同一批文档做 3 种切分策略，用固定的 20 道题测 Recall@5，记录实验表格。
- 验收：能拿出一份"切分参数 → 召回率"的实验记录，而不是拍脑袋定 chunk size。

### S3 检索与重排（1.5 周）★核心竞争区

**目标**：把召回率和排序质量做到可解释、可优化。

- 召回：dense / sparse / hybrid，RRF 融合，多向量（ColBERT 思路）。
- Query 理解：改写、多查询扩展、HyDE、子问题拆解、意图路由。
- 过滤：元数据/时间/权限过滤；**预过滤 vs 后过滤**对召回的影响（这是权限正确性的关键）。
- 重排：cross-encoder（bge-reranker）、LLM rerank 的成本与延迟取舍。
- 上下文组装：去重、邻近块扩展、token 预算分配、引用编号。
- 动手：在 100 题评测集上做 A/B：
  1. 纯向量；2. 混合召回；3. 混合 + rerank；4. 再加 query 改写。
  记录 Recall@k、nDCG@10、P95 延迟、单次成本。
- 验收：能画出完整"召回漏斗"（候选 → 过滤 → 重排 → 入 prompt），并指出瓶颈在召回还是排序。

### S4 生成与编排（1 周）

**目标**：让答案可信、可追溯、该拒答时拒答。

- 概念：grounded generation、引用标注、无答案判定、多轮指代消解、会话压缩、流式输出。
- 编排：工作流 / Agent、工具调用、多模型路由与降级。
- 动手：
  - 实现 answer-with-citations（引用可点击回溯到原文段落）；
  - 构造 20 道"知识库中没有答案"的问题，测拒答率与误拒率；
  - 做一次 prompt 模板 + 模型组合的对比实验。
- 验收：引用能定位到原文；无答案问题拒答率 > 80% 且误拒率可接受。

### S5 评测与可观测（1 周，越早开始越好）★分水岭

**目标**：把"感觉"变成"数字"。

- 指标：
  - 检索：Recall@k、MRR、nDCG、命中率；
  - 生成：faithfulness（忠实度）、answer relevancy、context precision/recall；
  - 业务：解决率、人工采纳率、平均轮次。
- 方法：评测集构建（真实问题 + 标准答案 + 金标文档片段）、LLM-as-judge 及其位置/长度偏差、回归测试。
- 工具：RAGAS、TruLens、Langfuse / LangSmith、OpenTelemetry trace。
- 动手：建 100–200 题评测集，接入 CI，每次改动自动跑回归并输出对比报告。
- 验收：任意一次改动，能给出"哪个指标变了、变了多少、归因到哪一环"。

### S6 工程化：权限、多租户与部署（1 周）★企业硬指标

**目标**：从 demo 走到可交付。

- 权限：文档级 / 行级 ACL 模型；权限同步（LDAP / SCIM / 组织架构）；**过滤下推到检索层**（防越权，不能检索后再删）；审计日志。
- 多租户：隔离级别（独立库 / 独立表 / 行级 tenant_id）、配额与限流。
- 部署：私有化、信创适配、容器化、水平扩展、缓存策略。
- 成本：embedding 与 rerank 的调用量估算、Token 成本核算。
- 动手：给现有系统加"部门隔离"，并写 10 条越权测试用例（含跨部门、跨租户、已删除文档）。
- 验收：越权测试全绿；能估算 100 万文档规模下的月度成本与 P95 延迟。

### S7 进阶方向（选 1–2 个，各 3–5 天）

- **Agentic RAG**：计划 → 检索 → 反思 → 再检索的循环；Self-RAG、CRAG 的批判与纠错机制；把检索暴露为工具原语。
- **GraphRAG**：实体关系抽取、社区摘要、多跳与聚合型问题；成本与更新代价。
- **多模态检索**：图表、图片、版面理解；跨模态 embedding。
- **长上下文 vs RAG**：什么场景下直接把文档塞进上下文更划算，边界在哪。
- 动手：任选一个做可运行 demo，并用 S5 的评测集与基线对比，给出"是否值得上"的结论。

## 3. 八周节奏表

| 周 | 主题 | 周末交付物 |
|---|---|---|
| W1 | S0 + 跑通朴素 RAG | 100 行以内的 naive RAG，能对 50 份文档问答 |
| W2 | S1 解析攻坚 + 建首批评测题 | 解析 pipeline + 30 题评测集（含金标片段） |
| W3 | S2 切分实验 | 3 种切分策略的 Recall@5 对比报告 |
| W4 | S3 混合召回 | 向量 vs BM25 vs 混合（RRF）的对比报告 |
| W5 | S3 重排 + 上下文组装 | 加 rerank 的 A/B 报告（质量 / 延迟 / 成本三角） |
| W6 | S4 生成 + S5 评测闭环 | 带引用与拒答的问答 + 100 题评测集接入 CI |
| W7 | S6 权限与部署 | 部门隔离方案 + 越权测试用例 + 成本估算 |
| W8 | S7 进阶 + 复盘 | 一个进阶 demo + 全链路复盘文档 |

> 如果只有 4 周：W1–W2 合并，W3–W5 合并为"检索攻坚"，W6 评测必做，S6/S7 选做。

## 4. 项目阶梯（能力证明）

按顺序做，每个都是可展示的产出：

- **P0 最小可用**：50 份文档，单文件脚本，带引用的问答。
- **P1 检索优化**：混合召回 + rerank，有量化对比报告。
- **P2 评测闭环**：100+ 题评测集 + CI 回归 + 归因分析。
- **P3 权限隔离**：多部门/多租户 + 越权测试。
- **P4 生产化**：增量同步、删除感知、监控告警、成本核算。
- **P5 进阶**：Agentic RAG 或 GraphRAG，并与基线做评测对比。

简历/汇报时，**P2 和 P3 比 P0 有说服力得多**——它们证明的是"可运营"而非"能跑"。

## 5. 精选资源

**论文（按学习顺序）**
1. Lewis et al., *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks* (2020) — 原始定义。
2. Liu et al., *Lost in the Middle* (2023) — 上下文位置偏差，解释为什么要重排与压缩。
3. Malkov & Yashunin, *HNSW* — 向量索引的工程基础。
4. Khattab & Zaharia, *ColBERT* — 多向量/迟交互检索。
5. Asai et al., *Self-RAG*；Yan et al., *CRAG* — 反思与纠错式检索。
6. Edge et al., *GraphRAG* (Microsoft) — 图谱路线的代表。
7. Es et al., *RAGAS* — 评测框架的指标定义。
8. Anthropic, *Contextual Retrieval* — 切分上下文增强的工程实践。

**文档与源码**
- Milvus / Qdrant 官方文档（索引参数与过滤语义）。
- Elasticsearch / OpenSearch 的 hybrid search 与 RRF 实现。
- LlamaIndex、LangChain 的检索抽象（读设计，不必全用）。
- 开源项目读码：RAGFlow（解析链路）、Dify（编排与工作流）、FastGPT（知识库产品化）。

**建议的读码方式**：带着"它的召回漏斗长什么样、权限在哪一层过滤、评测怎么接"三个问题去读，比通读源码有效。

## 6. 阶段自测清单

每完成一个阶段，能不看资料回答：

- [ ] 向量检索和 BM25 各自会在什么 query 上失效？混合时如何融合分数？
- [ ] 双栏 PDF 解析错乱会导致什么下游问题？如何在评测中暴露它？
- [ ] chunk 变小为什么召回率会升、但生成质量可能降？父子块怎么解决？
- [ ] 预过滤和后过滤在权限场景下分别有什么风险？
- [ ] rerank 提升了 nDCG，但端到端答案没变好，可能是什么原因？
- [ ] 如何判断一次答错是"没召回"还是"召回了但没用好"？
- [ ] LLM-as-judge 有哪些系统性偏差？如何校准？
- [ ] 文档被删除后，索引、缓存、引用分别要怎么处理？
- [ ] 什么情况下应该放弃 RAG，改用长上下文或结构化查询？
- [ ] 100 万文档、100 QPS 的场景，瓶颈最可能出现在哪一层？

## 7. 常见坑

1. **先学框架再学原理**：会调 LangChain 但答不出"为什么召回不到"，等于没学。
2. **没有评测集就开始优化**：所有"效果变好了"都无法证伪，最后变成玄学调参。
3. **只盯 chunk size**：解析质量和 query 改写的收益通常远大于切分参数微调。
4. **权限后加**：检索后再过滤会导致"先越权拿到再删"，既漏数据又泄露给日志；权限必须是检索的前置条件。
5. **迷信 GraphRAG / 长上下文**：两者都有明确的成本与适用边界，先证明基线不够用再上。
6. **用干净样例数据自嗨**：真实文档的解析失败率才是项目风险所在。
7. **忽略删除与更新**：知识库不是只增不减，删除感知和增量重建是生产必答题。

## 8. 一页纸速记

```
解析 → 切分 → 索引 → 召回 → 过滤 → 重排 → 组装 → 生成 → 引用
  ↑                                              ↓
  └──────────── 评测（贯穿始终） ←───────────────┘
                权限（前置约束，不是后处理）
```

四项真正拉开差距的能力：**解析质量、召回+重排、权限过滤、评测闭环**。
