**参考版 A（论文口径，5 句）**：

1. 文档先被解析成纯文本，再切成块，每块用文档编码器压成一个向量，全部灌进 ANN 索引，这一步离线做一次。
2. 用户提问时，问题用同一个编码器压成向量，去索引里找最相近的 k 个块——这就是「非参数记忆」的读取。
3. 取回的块要么整体喂给生成器（同一批文档管整段答案），要么逐 token 动态挑文档，两种口径对应 RAG-Sequence 与 RAG-Token。
4. 训练时不知道「该用哪篇文档」，于是把文档当潜在变量，用生成损失反传梯度，检索器因此学会「为这个任务找文档」。
5. 这样知识就存在索引里而不是权重里：换索引即更新知识，答案能指回原文——代价是「检索不到就全盘失效」。

**参考版 B（8 环口径，5 句，2026-11-23 10:05 给出，供对照）**

> ① 语料 → ② 解析：从 PDF / Word / 网页等来源抓来一批文档，解析成纯文本加基础结构（标题层级、段落）。【丢：版面坐标与阅读顺序、表格的行列关系、图片里的字（除非另做 OCR）、以及「文档之外的世界」】
>
> ③ 切分 → ④ 编码：按标题和长度把文本切成 chunk，用同一个 embedding 模型把每个 chunk 编码成定长向量（bge-small 是 512 维）。【丢：跨 chunk 的上下文，切点落在句子中间时语义被劈开；编码只保留语义方向，丢字面与词序】
>
> ⑤ 索引：把向量批量写进 ANN 结构（HNSW / IVF），离线一次，供在线快速近邻。原文另存一份，索引里只有向量和指针。【丢：精确 top-k 的保证——ANN 是「大概率找到」，换来的是毫秒级而不是全表扫】
>
> ⑥ 检索 → ⑦ 重排：用户提问，问题用同一个模型编码，去索引找最相近的 k 条候选，回表取原文；再用交叉编码重排模型对这 k 条逐条重打分，取前 n 条。【丢：k 之外的召回（长尾就没了）；重排只在这 k 条里比，候选外的好文档永远进不来】
>
> ⑧ 生成：把 n 段原文和问题拼进 prompt，连同历史对话一起塞进上下文窗口，模型据此写出答案并标注引用序号。【丢：超出上下文预算的文档被截断；语料里没有的知识它只能编（幻觉）；答案只覆盖被选中的那 n 段】

**最终该记住的 4 件事**（不是 5 句原文，是 5 句背后的判断）：

1. **起点是「语料」不是「系统」**——文档从哪来、什么格式，决定了解析器，也决定了天花板。RAG 的输入端是世界，不是数据库。
2. **编码与索引必须拆开**——编码丢字面与词序（所以需要 BM25 补），索引丢精确 top-k（所以需要过采样 + 多路）；「索引里只有向量和指针，原文另存」是 D02/D03 的前提。
3. **检索与生成之间有一环重排**——向量相似度答「像不像」，交叉编码答「答不答得上」。这环论文里没有，是工程补的。
4. **每一环都要说得出「丢什么」**——这是整条链路唯一的不可逆性来源，也是 D06 误差归因的分类依据。

## 五、练习记录：矩阵版 Top-3（2026-11-23 19:13）

### 代码（原样保留，未改动）

```python
sim2 = sim.copy()
np.fill_diagonal(sim2, -np.inf)               # 把自己排除
top3 = np.argsort(-sim2, axis=1)[:, :3]       # (N, 3)
```

**判定：过。** 三个决定都对：先 `copy` 不污染原矩阵、用 `-inf` 而非事后过滤、`axis=1` 按行独立取前 3。

### 判卷提出的两点（不影响当前结果，影响以后写类似代码）

| # | 问题 | 说明 |
|---|---|---|
| 1 | `-sim2` 把 `-inf` 变成 `+inf`，靠"升序时 +inf 排最后"实现排除 | 逻辑正确但需一步隐含推理；注释应写机制（"变号后必在末尾"）而非只写目的 |
| 2 | `k >= N` 时会把自己选进来 | `-inf` 只是把自己分数做小，没有减少候选数；`N=3, k=3` 时自己排第 3 仍被取到。加 `assert k < N` 或从 `N-1` 里取 |
