**命令**：`.venv\Scripts\python.exe code\day01_embedding_demo.py`
**产物**：`code/day01-demo-output.txt`（全文归档，含矩阵与 Top-3）

**设置**：10 句中文，其中 #5「苹果手机多少钱一台？」/#6「苹果多少钱一斤？」为同词歧义对照组；bge-small-zh-v1.5 本地离线，512 维。

**关键输出**

| 项 | 结果 |
|---|---|
| 句数 × 维度 | 10 × 512，float32 |
| encode 输出模长 | min=max=1.000000（**bge 自带 Normalize 模块**，`normalize_embeddings=False` 也关不掉） |
| 手工余弦 vs 归一化点积 | 最大绝对差 2.384e-07（float32 舍入，即等价） |
| 反证：把 #1 放大 3 倍 | 点积 0.6475 → 1.9426，余弦仍是 0.6475 |
| 非对角相似度区间 | **[0.189, 0.826]** |
| 全场最高非对角 | **#5 vs #6 = 0.8256**（苹果对子） |
| 语义同类对照 | #0 vs #1 = 0.6475（RAG 两句） |

**四条结论**

1. **归一化让内积 = 余弦**，条件是两者模长都为 1；点积会随模长漂移，所以工程上要么模型内建 Normalize（bge 就是），要么在入库/查询前显式除模长。
2. **相似度绝对值没有意义**：0.19–0.83 这个区间只在「同一个 query 内部排序」时有含义，不能拿 0.8 当「相关」阈值（不同模型、不同语言、长短句都会整体平移）。
3. **同词歧义没有被拉开**：苹果对子 0.8256 是全表最高分，比语义真正同类的 RAG 对子（0.6475）还高。用「苹果手机多少钱」去检索，Top-1 会命中「苹果多少钱一斤」——**这是今天最值钱的负结果**，它直接证明纯稠密检索不足，D04 的 BM25 与第 2 周的重排就是为了治这类错。
4. **底噪约 0.25–0.36**：无关句之间也有 0.25 左右相似度，说明「绝对阈值过滤」不可靠；正确做法是 top-k 截断 + 重排，而不是「小于 0.5 就丢」。
